# DataGuard 未完成項目清單

**建立日期：2026-05-17**

本文件記錄目前尚未完成的功能缺口、測試缺口與設計遺留問題，

## 一、功能缺口（影響使用者）

### 1. 自動偵測檔案編碼（encoding detection）

**說明：**
`src/dataguard/parser/encoding.py` 實作了 `detect_encoding()`，使用 `chardet` 偵測編碼，
但 `CsvParser.parse()` 與 `JsonParser.parse()` 都預設直接使用 `utf-8`，
從未呼叫 `detect_encoding()`。
CLI 也沒有自動偵測，非 UTF-8 的檔案（如 latin-1 編碼的 CSV）會因解碼錯誤而失敗。

**影響：**
讀取非 UTF-8 的資料來源時，程式報錯而非自動處理。

**建議做法：**
- 在 `CsvParser.parse()` 與 `JsonParser.parse()` 中，若未傳入 `encoding` 參數，
  先呼叫 `detect_encoding()` 取得編碼後再開檔
- 新增 non-UTF-8 fixture（例如 latin-1 編碼 CSV）
- 新增 integration test 驗證自動偵測行為

**相關檔案：**
- `src/dataguard/parser/encoding.py`
- `src/dataguard/parser/csv_parser.py`
- `src/dataguard/parser/json_parser.py`

---

### 2. Schema `type: float` 驗證器缺失

**說明：**
`ColumnSchema.min` / `max` 型別已宣告為 `float | None`，
`type_cast` transformer 也支援 `target_type: float`，
但 `src/dataguard/schema/registry.py` 沒有 `FloatValidator`。
若 schema YAML 定義 `type: float` 的欄位，驗證時會拋出：
```
ValueError: Unsupported validator type: float
```

**影響：**
使用者無法在 schema 中定義浮點數欄位的驗證規則。

**建議做法：**
- 新增 `src/dataguard/schema/validators/float.py`，參考 `IntegerValidator` 實作
- 在 `registry.py` 新增 `float` 分支
- 新增 unit tests

**相關檔案：**
- `src/dataguard/schema/registry.py`
- `src/dataguard/schema/validators/numeric.py`（可擴充或新增 float.py）

## 三、設計遺留問題（不影響現有功能，但影響程式碼品質）

### 6. `case_sensitive` 欄位宣告但無作用

**說明：**
`src/dataguard/schema/models.py` 的 `ColumnSchema` 有 `case_sensitive: bool = True`，
但 `EnumValidator` 和 `StringValidator` 都沒有讀取此欄位。
使用者在 schema 設定 `case_sensitive: false` 不會有任何效果。

**建議做法（二選一）：**
- 實作：讓 `EnumValidator` 與 `StringValidator` 支援 `case_sensitive: false`（大小寫不敏感比對）
- 移除：若不打算支援，從 `ColumnSchema` 移除此欄位，避免誤導使用者

---

### 7. `WARNING` level 定義但從未產生

**說明：**
`ValidationResult.level` 支援 `Literal["PASS", "WARNING", "ERROR"]`，
`assemble_report()` 也計算 `warning_count`，
但目前沒有任何 validator 產生 `level="WARNING"`，report 中的 `warning_count` 永遠為 0。

**建議做法（二選一）：**
- 實作：定義哪些情況應該回傳 WARNING 而非 ERROR（例如：超出範圍但仍合理，或可選欄位格式建議）
- 簡化：若 WARNING 不在設計範圍內，從 model 移除此 level，避免混淆

---
